What this tool is for

You give it a suspicious script. It gives you back readable code, a list of indicators, and a report you can hand to someone else.

  • Reads the script for you — PowerShell, VBScript, JScript, batch and cmd all get unpicked into plain text.
  • Finds the indicators — including ones the script only assembles as it runs.
  • Checks them automatically — every indicator is looked up as part of the analysis, not as a separate errand.
  • Tells you where they are — country, city, ASN and reverse DNS for every address.
  • Lets you decide — your verdict on each finding.
  • Writes it up — a PDF, plus Excel and CSV.

Nothing is ever executed. Every transform rewrites literal values only. There is no eval, no sandbox, and no PowerShell process — so a hostile script cannot do anything by being analyzed.

Getting around

The dark sidebar is on every page. Analyze is the home page, History lists what you've already run, Tutorial is here, and Settings holds API keys and preferences. The Pocolo portrait at the top starts the guided tour from wherever you are.

Anything that takes a moment — running an analysis, building a PDF — dims the screen and shows what it's doing, so you never wonder whether a click registered.

1. Analyze page

Analyze a Script

  1. Paste a script into the big box — PowerShell, but also VBS, JScript, batch or a raw log line.
  2. Or use the drop box: click Choose files, or drag files from Explorer — anywhere on the page works, not just the box. Accepted: .ps1 .txt .vbs .js .bat .cmd .log, or a .zip containing them.
  3. Submitting more than one file? Separate reports gives one PDF each and lands on History with the batch already selected; Combined report returns a single document covering all of them.
  4. Leave Skip threat-intel lookups unticked and every indicator found is checked automatically, and every address located. Tick it only when you're offline or have no keys — deobfuscation and extraction still run.
  5. Click Analyze. One file opens its result page; several files (or a zip) are each analyzed separately and you land on History.

Multiple files at once is the fast path for a folder of samples. A submission is capped at {{ batch_limits.entries }} files, {{ batch_limits.entry_mb }} MB each and {{ batch_limits.total_mb }} MB in total, whether they arrive loose or in an archive — and directory paths inside a zip are discarded, so a crafted archive cannot write outside the extraction area.

Quick IOC Lookup

  1. Have a single indicator rather than a script? Put it in the second card and check it directly. Nothing is stored in History.
  2. Leave the type on Detect automatically and the shape of the value decides: IP, domain, URL or hash.
  3. Or pick one explicitly — IP address, Domain, URL, File hash or Malware signature / family.

A signature is a family name like AgentTesla or Formbook. It has no recognisable shape, so auto-detect can never find it — choosing the type by hand is the only way to reach that lookup. It is checked against MalwareBazaar, the way the original Plaguards' signature query worked.

2. Result page — left pane

Deobfuscated Script

  1. The result is shown reformatted, one statement per line. If nothing could be rewritten the page says so plainly rather than implying the input is clean.
  2. “N deobfuscation transform(s) applied” opens the transform log — every pass that changed something, in the order it ran.
  3. “N variable value(s) statically resolved” is the table of variables rebuilt by following assignments in order. This is usually where the real C2 address, port or mutex finally appears.
  4. A resolved value can still be a stage rather than the payload — a Base64 blob, or a list of character codes. Those are decoded again and the plaintext shown underneath, so a multi-stage peel reads end to end instead of stopping at a wall of digits.
  5. “Show original input” reveals exactly what you submitted, untouched, for comparison.

Resolved values are reconstructed by folding literals through concatenation, Base64, -join, -replace, [char] casts and friends. Nothing runs to obtain them, and the values are defanged before display.

3. Result page — findings and triage

  1. Every finding is a card colour-coded by severity: IPs, domains, URLs, hashes, registry keys, mutexes, User-Agents and suspicious code signatures. High-severity cards start open.
  2. Click a card to see its context (the surrounding source), its MITRE ATT&CK technique where one maps cleanly, and threat intel.
  3. Expand all / Collapse all work through the list quickly.
  4. Each card carries Confirm Threat, False Positive and Unknown. Mark all as applies one verdict to every finding in a single request.

Severity describes the technique observed, not confirmed impact. A download cradle is High because that is what cradles are, not because this sample is proven malicious. Your verdict is what the report treats as authoritative.

4. Threat intelligence

  1. Indicators are checked against whichever of the seven providers you've configured under Settings.
  2. Each finding shows one headline verdict; open details for the per-provider breakdown. Click any row to open that provider's own page for the indicator in a new tab.
  3. Reserved or non-routable values are marked Not applicable with the reason, instead of being queried pointlessly.
  4. Results are cached locally, so re-running the same sample doesn't spend your quota twice. --no-cache on the CLI bypasses that.

A documentation IP or a .invalid domain can never have a reputation. Querying them wastes rate-limited quota and returns confusing HTTP errors, so they are ruled out up front — but anything a provider will genuinely answer for is still asked.

5. Where the addresses are

  • Every IP found is located: country, city, coordinates, continent, ASN, organisation, network and reverse DNS.
  • Each one is also categorised — public, private, documentation, loopback — so a reserved address is not presented as a real location.
  • Point Settings → General at a MaxMind GeoLite2 database and this runs entirely offline.
  • No database? Add an ipinfo.io token instead. With neither, geolocation is simply skipped.

A reputation verdict says whether an address is known bad. Geolocation says whether traffic to it makes sense at all — a share reaching a host two continents away is worth a question even when no provider has ever heard of it.

6. Reports

  1. View Report opens the PDF in a new tab; Download Report saves it.
  2. Tick Redact IOC values first to print every indicator black-on-black — present in the file, unreadable at a glance.
  3. From History, select several analyses and choose Combined report for one document covering all of them, or Export as zip for separate PDFs.

Each report opens with a cover, a table of contents and a formal disclaimer notice — none of them numbered. Page 1 is the analysis summary. After that come the findings table, per-finding detail grouped by severity, the transform log and resolved variables, then Appendix A (the deobfuscated script) and Appendix B (the original input). Every contents entry is clickable and quotes the page it starts on.

All indicators are defanged in the document, so nothing in a report you email around is clickable or resolvable by accident.

6. History page

  1. Past analyses, newest first, with the file name, when it ran, the finding count and how many were high severity.
  2. View reopens an analysis, triage verdicts and all.
  3. Tick rows (or Select all) to Export as zip, build a Combined report, or Delete Selected.
  4. Only the most recent are kept — set how many under Settings → General. Older ones are pruned automatically after each run.

7. Settings page

  1. Threat Intel API Keys — one field per provider. A green box means configured, red means that provider is skipped. Each row links to where you get a key. Saving a blank field leaves the stored key alone.
  2. Geolocation Databases — one field each for MaxMind's GeoLite2 City, Country and ASN. Each accepts a .mmdb, a folder, or the .tar.gz exactly as downloaded. Fill in any mix and they are merged into one record per address; the section carries step-by-step instructions for obtaining them.
  3. General — how many analyses to keep, the analyst or organisation name printed on reports, and the UTC offset used for every timestamp in reports and History.
  4. Danger Zone — clears every stored analysis, finding and triage decision. API keys and general settings survive it.

Keys live in the local SQLite database on this machine. Only the extracted indicator value is ever sent to a provider — never your script, and never the surrounding context.

9. Command line

Everything above is available headless, for scripting a queue of samples:

  1. python -m plaguardsv2.PlagCLI analyze sample.ps1 — or pipe the script in on stdin.
  2. --pdf FILE and --json FILE write the same report and results you'd get in the browser; --redact-iocs produces the redacted copy.
  3. --no-intel, --no-cache and --no-store control lookups and persistence; --triage walks you through the findings interactively.

The CLI and the web UI share one database, so anything you analyze from a terminal shows up in History — and anything you triage in the browser is reflected in a report generated later from the command line.
